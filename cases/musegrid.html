Context and Problem Discovery

Music tutors, annotators, and arrangers regularly lose time switching between two incompatible categories of software. Notation programs produce clean 5-line sheet music and MusicXML exports, yet make it cumbersome to adjust expressive performance timing, edit note velocities, or record live microphone takes beside a score.

Digital audio workstations handle piano-roll editing and recording well, yet routinely struggle to preserve readable 5-line notation, enharmonic spellings, ties, and slurs across MIDI round-trips.

Bringing both workflows into a single cross-platform application across Web browsers, desktops, iOS, and Android introduces strict engineering constraints. Splitting playback and recording across independent audio packages causes hardware clock drift, while packing WAV audio and SoundFonts into compressed archive files causes severe write amplification and browser memory pressure.

System Exploration and Discarded Iterations

Before locking the architecture, I evaluated four common cross-platform design paths and discarded the approaches that failed real-time audio safety or browser stability constraints:

Separate Playback and Recording Packages

Combining independent Flutter playback and recording plugins opens two separate audio device contexts, creating clock drift and iOS AVAudioSession routing conflicts.

Destructive Tick-to-Staff Regeneration

Rebuilding 5-line staff notation from raw MIDI ticks after every Piano Roll edit erases enharmonic spellings, manual voice assignments, beams, slurs, and barline ties.

Bundled .zip Project Archives

Packing MusicXML, SoundFonts, and multi-minute WAV recordings into .zip bundles causes 2x temporary disk spikes, high CPU overhead, and Wasm heap pressure on small edits.

5-Layer + Middle Bridge Architecture with Unified Duplex Audio and CAS

A strict downward-only dependency stack separating Pure Dart musical logic (960 PPQN dual-model sync and MusicXML) from a shared C/C++ and Emscripten Wasm duplex audio core, lock-free SPSC ring buffers, and SQLite plus Content-Addressed Storage.

Every module depends only downward across five isolated layers and a platform-agnostic Middle Bridge:

Layer 5 Flutter UI

Presentation: 5-Line Staff, Custom Piano Roll, and Metering

Interactive staff engraving rendered with the Bravura SMuFL font via crisp_notation, paired with a viewport-culled Piano Roll CustomPainter and an isolated 30 to 60 Hz playhead and peak/RMS meter overlay.

Layer 4 Pure Dart

Musical and Notation Domain (WasmGC-Ready)

Owns the 960 PPQN integer tick timeline, tempo and time-signature conversion, undo/redo command bus, bidirectional MusicXML and compressed .mxl codecs, and in-place dual-model synchronization.

Middle Bridge FFI / Wasm

Segregated Audio Contracts and Platform Storage Adapters

Decouples Pure Dart interfaces from native dart:ffi audio calls, Web AudioWorklet MessagePort streams, and local persistence (native SQLite FFI versus Web sqlite3.wasm over OPFS).

Layers 1 to 3 C/C++ & Wasm

Real-Time Audio Engine, SPSC Queues, and Duplex HAL

Combines miniaudio full-duplex I/O (native) and AudioWorkletProcessor (Web) with lock-free SPSC ring buffers, a zero-allocation 3-phase audio cycle, FluidSynth SF2 playback, and a non-real-time Butler WAV worker.

Core Music Technology and Audio Architecture

Running notation, SoundFont playback, and microphone recording concurrently across desktop, mobile, and browser runtimes required deterministic boundaries across timing, audio threads, and disk I/O:

Loop 1: Lookahead Playback
Epoch-Gated Event Scheduling

A non-paint timer feeds sorted MIDI events inside a rolling 200 ms lookahead window, issuing monotonic epoch invalidation on seek or live edits to prevent stale notes.

Loop 2: Duplex Capture
Finalize-Then-Hash WAV Pipeline

Audio callbacks copy microphone frames and latch hardware sample timestamps into a lock-free ring buffer while the Butler worker encodes raw WAV headers and computes SHA-256 digests off-thread.

Loop 3: Telemetry Sync
Single-Drainer 30 to 60 Hz Meters

Real-time frames emit playhead positions, L/R/In peak and RMS values, underrun flags, and live waveform blocks without triggering full Piano Roll repaints.

  • Dual-Model Timing and MusicXML Round-Trips: Every note stores both quantized sheet timing and raw expressive timing linked by a shared identifier, supporting straight subdivisions up to 1/64, dotted subdivisions up to 1/32., and triplets up to 1/32T while keeping .musicxml, .xml, and .mxl import and export intact.
  • 3-Phase Real-Time Audio Safety: Each audio callback executes a strict start, process, and end cycle with zero heap allocations or mutex locks. On Web without SharedArrayBuffer, SoundFont loading runs strictly while transport is stopped under a fail-closed memory byte cap to prevent mobile Safari AudioWorklet crashes.
  • Hybrid SQLite and Content-Addressed Storage: Authoritative score tables live in SQLite (WAL mode on native, rollback journal inside OPFS Web Workers on browser) using UUIDv7 keys and revision counters, while immutable .sf2 SoundFonts and recorded .wav takes are deduplicated by SHA-256 digest and reclaimed via mark-and-sweep garbage collection.
  • Fail-Closed Browser Storage Guards: On Web startup and prior to recording or SoundFont import, the storage adapter requests persistent storage permission and checks remaining quota before writing to OPFS.

Practical Outcomes and Verification

Functional Prototype Verification (v0.1.0)

MuseGrid implements multi-part 5-line notation, dynamic Piano Roll editing, GeneralUser GS and custom SoundFont playback, full-duplex WAV microphone recording with round-trip latency calibration, MusicXML and MXL import/export, and local SQLite/OPFS project management across Web, desktop, and mobile targets.

To let reviewers test the platform immediately without installing Xcode, Android NDK, or C++ toolchains, prebuilt WebAssembly audio and database binaries are packaged directly inside the Web target alongside a clean-machine setup guide covering Windows, macOS, Linux, iOS, and Android.

Following a disciplined milestone boundary, user experiment telemetry, web administrative portals, remote cloud delta-sync (already slotted behind Pure Dart repository contracts), and AI-generated music notation workflows were scoped as Phase 2 extensions built atop this verified audio and notation foundation.

Lessons Learned and Retrospective

Cross-platform music platforms fail when audio threading, browser storage limits, and notation state are coupled prematurely. Isolating real-time DSP inside lock-free ring buffers, enforcing fail-closed browser memory and storage checks early, and separating expressive timing from sheet engraving via stable note IDs established an architecture ready for classroom testing, cloud sync, and AI notation pipelines.
